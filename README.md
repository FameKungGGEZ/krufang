## Getting Started

1. Run `npm install`
2. Run `npm run dev`

## Supabase setup

1. Copy the Project URL and **anon/public** key from Supabase into `.env`:

   ```dotenv
   VITE_SUPABASE_URL=https://YOUR_PROJECT.supabase.co
   VITE_SUPABASE_ANON_KEY=YOUR_ANON_PUBLIC_KEY
   ```

   Never put a `service_role` key in a Vite environment variable.

2. Review the current database first by running [`supabase/export-current.sql`](./supabase/export-current.sql) in the SQL Editor. The export shows every product/category row, table policies, and the existing `covers` / `free-products` bucket settings.
3. Run [`supabase/setup.sql`](./supabase/setup.sql) in the SQL Editor. It adds only the missing fields (`categories.ink`, `categories.icon`, and product preview metadata), upserts the six catalog categories and inserts eight demo products without deleting existing product rows, preserves existing RLS/auth policies, and allows any MIME type in the existing `free-products` bucket. Demo products without an actual downloadable file are inserted as drafts. If setup was already run, run [`supabase/allow-all-download-types.sql`](./supabase/allow-all-download-types.sql) to apply the bucket setting without reseeding.
4. Assign trusted admin users the `role: "admin"` claim in **app_metadata** using a trusted Supabase server/admin workflow. Do not set an admin role in user-editable `user_metadata`. The existing database policies authorize writes using this claim.
5. Restart the Vite development server after changing `.env`.

The storefront reads published products and categories from Supabase. Admin sign-in uses Supabase Auth and checks the existing `app_metadata.role` admin claim. Product/category changes are guarded by the existing RLS policies. Covers and free download uploads use the existing `covers` and `free-products` storage buckets; storage upload permission depends on the Storage policies already configured in the project.

The setup script is idempotent for its seeded UUIDs and category names. It does not delete or overwrite the existing `test` rows. Treat database exports as private because product rows can contain file URLs.
